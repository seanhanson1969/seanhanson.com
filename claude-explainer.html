The work order
📋
Task
A work order with a specific scope. Not a conversation — a job. "Complete this. Deliver that. Done."
click to flip →
What it actually is
Task
A defined unit of work Claude completes and hands back
A task is a specific, bounded assignment — not an open-ended chat. You define what you need, Claude does it, and returns a result. Think of it as the difference between "let's talk about dinner" and "make a reservation for two at 7pm."

How they fit together — a real example from Sean's day

Cowork Every morning, Cowork runs Sean's Daily Briefing skill automatically — pulling his calendar, flagged emails, and task list into one document before he even opens his laptop.
Chat Sean opens Claude.ai Chat and asks for help drafting a section of a safety procedure. It's a back-and-forth: Claude suggests language, Sean revises, they go a few rounds.
Agent For a bigger research job — like summarizing a long policy document — Sean hands it to Claude as an agent task. Claude reads, analyzes, and returns a summary without Sean in the loop for each step.
Code When Sean asks for something technical — like this HTML page — Claude Code is what actually builds it. Sean never opens a terminal. He just describes what he wants and gets a finished file back.
